# fork

유닉스 계열에서 프로세스를 복제하여 멀티 프로세스 구조로 멀티 태스킹 하기 위해 사용된다.
CPU가 복수일 경우 뛰어난 성능과 응답성을 보여줄 수 있다.

하지만 복제된 프로세스 사이 데이터 통신 처리에 드는 비용이 이 효율보다 더 크다면 성능이 하락한다.
복제된 프로세스들이 공통으로 사용하는 파일이나 I/O는 `mmap`을 사용하여 비용을 최소화할 수 있다. (`IPC` 참조)

# 사례

쉘에서 `ls` 명령어를 실행한다고 가정하자. 흐름은 아래와 같다.

1. 쉘은 `fork`로 자식 프로세스를 생성한다.
2. 생성된 자식 프로세스는 `exec`를 호출하여 `/bin/ls` 프로그램 이미지로 교체된다.

# 단점

`fork`는 부모 프로세스를 복제할 때 모든 정적 정보를 복재한다.
- 부모 프로세스의 힙 메모리
- 부모 프로세스의 정적 메모리
- IPC 자원 ID
- 열린 파일
- 시그널 마스크 등

하지만 위 사례에서도 보았듯이 `fork` 후 바로 `exec` 하는 경우 쓰지도 않는 자원을 복제하는 꼴이 된다.
이는 대형 시스템 및 실시간 처리가 중요한 서비스라면 문제가 될 수 있다.

# posix_spawn
`posix_spawn`은 부모 프로세스 자원을 선택적으로 복제 및 관리할 수 있다.
- 열린 파일
- 프로세스 그룹 ID
- 유저 및 그룹 ID
- 시그널 마스크
- 스케줄링
