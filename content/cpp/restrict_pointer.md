# aliasing
어떤 한 공간에 대해 여러 접근 경로가 있는 경우를 말한다.

```c
int *i_from; // int형의 변수를 에일리어싱
```

에일리어싱은 C언어에서 중요한 기능을 담당하고 있으며, 가독성 향상이나 형변환을 위해 사용되지만 때로는 최적화를 방해하거나 문제를 일으킬 수도 있다.

심지어 몇몇 함수들은 인수로 받아들이는 주소가 에일리어싱 되었을 때 오류를 방지하기 위해 미리 검사하는 행위 때문에 성능 저하가 발생한다.
따라서 함수 인수가 다른 곳에서 참조하지 않음을 보장해 준다면, 내부적으로 병렬처리하거나 에일리어싱에 대한 검사를 하지 않아도 되므로 효율적으로 함수를 설계할 수 있게 된다.

이를 위해서 `restric pointer`가 도입되었다.

# restrict pointer

`restric pointer`는 최적화와 신뢰성 있는 코드를 위해 도입되었다.

예를 들어 어떤 API는 임플리먼테이션에 따라 최적화나 신뢰성을 높이기 위해 독점적으로 메모리에 접근해야 할 필요성이 있다고 가정해 보자.
이 필요조건을 API를 구현하는 임플리멘테이션측에 강요하게 된다면 내부적으로 락 매커니즘을 넣게 된다.
이는 싱글 스레드 프로그램에서는 오히려 오버헤드가 되고, 옳지 못한 설계가 된다.

### restric pointer를 이용한 해결책
```c
void *memcpy(void *dest, const void *src, size_t n); // memcpy에 restrict pointer 적용 전
void *memcpy(void *restrict s1, const void *restrict s2, size_t n); // 적용 후 (C99 이후)
```

해결책은 `restrict pointer`를 사용하여 `restrict pointer`가 가리키는 객체를 다른 공간에서 에일리어싱하지 않도록 강제하는 것이다.
이 규약은 해당 주소는 배타적으로 유일한 곳에서만 사용된다는 것을 사용차측에 보장하도록 한다.
따라서 어떤 함수가 `restrict pointer`로 선언된 주소 공간을 사용할 때는 다른 사이드 이펙트를 신경 쓰지 않고 사용해도 된다.

위 코드에서, C99 이후 memcpy에서는 내부적으로 `s1`, `s2`의 접근이 비순차, 비동기적으로 진행되거나 병렬 처리 될 수도 있음을 암시한다.
또한 에일리어싱이 없다고 가정하므로 복사 작업 시 일일이 메모리 위치를 확인하는 작업을 추가하지 않아도 되므로, 오버헤드가 줄어든다.

만일 에일리어싱을 사용하지 않았다는 것을 확신할 수 없다면 `memcpy` 대신 `memmove`를 사용하도록 한다.
